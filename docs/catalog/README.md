# Candidate songs and chart preparation

`candidates.json` contains 100 **editorially prioritized, beginner-oriented candidates**: familiar folk and spiritual songs first, then children's songs, then seasonal songs. These groups provide simpler starting points than a current pop chart. The source leads include [PD Info's children's list](https://www.pdinfo.com/pd-music-genres/pd-children-songs.php), [Christmas list](https://www.pdinfo.com/mobile/pd-music-genres/pd-christmas-songs.php), and [historical folk collection](https://www.pdinfo.com/pd-music-books/one-hundred-english-folk-songs.php). This is **not** a measured global fame ranking. The list is dated 2026-09-24. Eighteen candidates now have chord-only charts and are included in the playable catalog; 82 remain pending.

The imported charts come from the [Public Domain Song Anthology](https://commons.wikimedia.org/wiki/File:The_Public_Domain_Song_Anthology_with_Modern_and_Traditional_Harmonization.pdf). `imported-review.json` identifies the PDF page, composition attribution, chord count, key transposition, and any slash bass notes omitted for each chart. The anthology's new harmonizations are [released under CC0](https://aperio.press/news/2020-03-17-public-domain-song-anthology/). Its underlying versions are identified as public domain in the United States; review other jurisdictions before promoting the catalog globally. These charts contain no copied lyrics, melody notation, or recording. A guitarist should still play through each imported chart on a physical instrument to confirm that the sequence and difficulty suit a beginner lesson.

## Free sourcing path

1. Verify the composition and a specific historical source for each title. [PD Info](https://www.pdinfo.com/public-domain-music-list.php) explicitly says its lists are research leads, not proof of public-domain status, and that status varies by country. Keep the publication, date, and jurisdiction evidence with the review record. [Library of Congress's America Singing collection](https://www.loc.gov/collections/nineteenth-century-song-sheets/about-this-collection/rights-and-access/) is an example of a collection explicitly marked free to reuse.
2. Verify composer or traditional attribution and fill `attribution` in `candidates.json`. [MusicBrainz core data](https://musicbrainz.org/doc/About/Data_License) is CC0 metadata, but metadata alone is not a music license.
3. Create a simple, original chord only practice reduction from an eligible historical score or recording. [Mutopia](https://www.mutopiaproject.org/contribute.html), [Wikimedia Commons](https://commons.wikimedia.org/wiki/Commons:Welcome/en), and [Open Music Archive](https://openmusicarchive.org/) are possible sources; check the individual item's terms and the composition, arrangement, and recording separately. Avoid copying modern lyrics or charts. Record the source, rights review, and musical review in `REVIEW_TEMPLATE.md` or a structured review record.
4. Write the reviewed chord sequence as `docs/catalog/charts/001.txt` for rank 1, `002.txt` for rank 2, and so on. Cadence accepts chord names, ChordPro brackets, and repeats. `pnpm catalog:prepare` rejects a present chart with missing attribution or unsupported chords. These songs still need a musician to check the harmony and difficulty.

## Publish as shared catalog entries

With Node 24, run:

```sh
pnpm catalog:prepare
```

The command reads the candidate list and any chart files, validates every present chart with Cadence's parser, and writes `packages/music/src/catalog-curated.ts`. Each ready song gets a stable `catalog:starter:NNN` ID and becomes part of `defaultSongs`. The database stores each catalog song once with no owner; every user can see it, while their practice positions remain per user. Personal songs continue to have owners and are not generated by this command.

Once a rank has been published, keep that rank assigned to the same composition: it is part of the stable catalog ID. Reordering the candidate queue after publication would give users a different song at the old ID.

Before publishing, verify the chart and review record, run the public checks, and release the versioned public packages. The private app consumes those tarballs; it does not keep a second copy of catalog data. New global IDs are inserted by the catalog seeder. If a chart changes after publication, increment its candidate `revision` before regenerating; the seeder updates the shared row and resets progress for that song because earlier positions no longer refer to the same chord sequence.
